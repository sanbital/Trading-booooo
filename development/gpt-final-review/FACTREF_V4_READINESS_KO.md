# GPT 최종 검수 V4: 근거 전송 오류 수정과 준비 상태

## 실제 발견

V3의 전체 검수 형식에 합성 시장자료를 넣어 실제 Responses API를 세 번 호출했다. 짧은 키 인증 시험이나 mock이 아니다. 세 응답은 각각 5,088ms / 3,782ms / 3,499ms였으며 코드 검증 결과는 모두 무효였다.

- `NUMERICAL_PROSE`: 자유 해석에 숫자가 들어갔다.
- `EVIDENCE_VALUE_MISMATCH`: 숫자 인덱스와 인용한 원본 값이 일치하지 않았다.
- `EVIDENCE_REFERENCE_INVALID`: 실제 근거 사전 밖의 인덱스를 선택했다.

따라서 V3 mock 통과나 단순 키 인증만으로 실사용 준비가 완료됐다고 볼 수 없다. 위 결과는 합성 입력에서의 전송·검증 시험이다. 실제 시장 판단이나 수익성 검증이 아니다.

## 수정 내용

V4 wire는 배열 인덱스 대신 `C_return_5m`, `O_volumeRatio` 같은 명시적인 근거 식별자를 선택한다. 서버는 그 식별자가 가리키는 불변 입력 snapshot의 숫자와 단위를 그대로 첨부한다. 모델이 틀린 숫자를 반환한 뒤 서버가 맞게 고치는 방식이 아니다. 새 schema는 모델이 숫자·단위 복사 필드를 추가하면 거부한다.

중복 assessment는 decision에서 결정되는 정규화 필드로만 생성한다. 모델이 선택한 PASS/VETO/ABSTAIN 자체를 변경하지 않는다. 후보 ID·snapshot hash·원래 조건·현재 근거·누락·오래된 응답 및 자유문 숫자 검증은 유지한다. 명시적인 근거 선택도 해석의 경제적 정확성을 보장하지 않는다.

모델은 `gpt-5.4-mini-2026-03-17` 그대로다. `reasoning.effort=none`, timeout 8초, 기존 snapshot 유효시간을 유지한다. V3의 보호 관측 후 실행권 반환과 완성 봉 요청 합치기도 유지한다. 기존 executor와 매매 정책은 이번 V4 수정에서 변경하지 않는다.

## 검증

- 실제 V3 기반 전체 회귀 테스트: 92/92 통과.
- 실제 executor 문법 검사 통과.
- executor·CEC0040·slot sizing·exit review 원본 불변 확인.
- 근거 식별자 오류·추가 숫자 필드·후보/해시 변경·잘못된 missing·불완전 입력·자유문 숫자 등의 거부 검사 포함.
- 증빙: `evidence/factref-v4/verification.json`, `tests.tap`.

V4의 실제 API 비교 검증 요청은 도구 보안 판정에서 차단됐다. 다른 경로로 우회하지 않았다. **V4 실 API 응답 성공률과 응답시간은 미확인이다.** V3에서 관측한 시간을 V4 성능으로 보고하지 않는다. V4가 더 좋은 수익을 낸다는 증거도 없다.

## 심사 저장소

심사 기록·일일 API 예약 테이블과 원자적 claim 함수는 별도 저장소 migration으로 설치했다. RLS와 서비스 전용 권한을 확인했고 `service_role`로 수행한 저장소 테스트 8개가 통과했다. 시험 행은 rollback했다. 유한한 예산 검증과 짧은 lock/statement timeout을 포함했다.

이 설치는 거래 테이블·거래 차단·레버리지·슬롯·스케줄러를 변경하지 않는다. 실제 운영 예산이나 자동 호출 승인도 생성하지 않는다.

## 실행 범위

이 기록은 **거래 준비·검수 오류 수정**이다. 실거래 재개 보고가 아니다. 운영 executor 배포, GPT ENFORCE 전환, 운영 API 예산 변경, circuit 해제 또는 주문 실행은 수행하지 않았다. 임시 검증 함수는 호출 비활성 응답만 반환하는 버전으로 종료했다.

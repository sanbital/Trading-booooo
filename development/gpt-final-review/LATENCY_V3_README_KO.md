# GPT 최종 검수 V3: 처리 지연 개선

기존 거래 모델을 교체하지 않는 소스 수정입니다. 운영 배포 또는 실거래 재개를 실행하지 않습니다.

## 수정

- 원래 조건과 현재 재가속을 검토하는 역할은 유지합니다. API 응답의 필드명과 근거 경로만 짧게 전송하고 서버에서 원래 형식으로 복원해 동일한 숫자·단위·후보·해시 검증을 수행합니다.
- 공통 프롬프트와 stable prompt_cache_key를 사용합니다. 과거 PASS를 다른 입력에 재사용하지 않습니다.
- 동일한 완성 봉 URL의 병렬 요청을 합칩니다. BTC 자료도 같은 URL일 때만 공유합니다. 원래 요청·수신 시각을 그대로 기록하며 실패 응답은 캐싱하지 않습니다.
- GPT가 처리 중인 동안 X1 보호 감시를 유지합니다. 유효한 PASS가 저장·검증된 경우 현재 관측과 감지된 보호 처리가 끝난 지점에서만 실행권을 반환할 수 있습니다. 이후 기존 일반 사이클이 보호·계좌 상태와 모든 진입 조건을 다시 검사합니다.
- 200 USDT, 3배, 계좌 최대 10슬롯, 하위 정책 상한, B06133/CEC0040, R5/P142, 보호·청산·정산·lease 정책을 변경하지 않습니다.

## 검증과 한계

79개 모의 테스트를 실행합니다. GitHub 검증에서는 실제 executor 구문과 상대경로 import를 검사합니다. 새 두 연결을 역으로 제거하면 기준 executor blob 80b79fb449ad01e4534bfa1076b75a142f887650과 같아야 합니다.

합성 출력 예시의 UTF-8 크기는 1,614→839바이트로 감소합니다. 이는 실제 모델의 토큰 사용량이나 지연이 같은 비율로 줄었다는 측정이 아닙니다. 가상시간 시험은 스냅샷 1초, PASS 4초, 기존 감시 종료 47초를 가정하며 개선 구조가 4초의 보호 관측 완료 후 재검사로 전환하는지 검증합니다. 주문은 실행하지 않습니다.

실제 API 응답속도, p50/p95/p99, 신선도 만료율, 거래 수익성은 이번 소스 검증으로 확정하지 않습니다. 보호 처리나 일반 사이클 재검사 자체가 오래 걸리면 PASS가 여전히 만료될 수 있습니다. 배포된 다른 인스턴스가 심사 중인 경우 로컬 완료 힌트가 없는 만큼 동일한 조기 전환을 보장하지 않습니다.

기본 OFF, 일일 API 예산·호출 상한 0은 유지합니다. 심사 저장소 SQL, 거래차단 해제, 운영 배포와 실거래 재개는 실행하지 않습니다.

실제 배포본과 새 코드 해시 일치, 주문 없는 실제 검수 API 시험, 심사 저장소 설치·권한 확인, API 예산 승인과 모드 확인이 필요합니다. 기존 안전차단은 최신 거래소 계좌·주문 대사와 해당 incident의 원인 확인 후 기존 운영 절차로 판단해야 합니다. 단순히 circuit_open을 false로 덮어쓰는 코드는 제공하거나 실행하지 않습니다.

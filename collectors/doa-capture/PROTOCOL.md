# Live capture protocol DOA-CAPTURE-1

Operator authorized production capture on 2026-09-25. This implementation amendment supersedes the draft's capture mechanics only, before any fresh observation. Trading authority remains empty; executor and gateway are unchanged. Capture does not improve decisions by itself. No LLM calls or orders are made.

The source hash of this file is checked by the worker and stored in the DB before activation. T0 and end are stored in doa_capture.control. One 14-day cohort, maximum 2,000 admitted V17 signals including rejected signals. DEV days 0–4, VALIDATION 4–9, TEST 9–14; exclude six hours before boundaries. Historical data is DEV only. No TEST inspection, tuning, reuse or automatic promotion. Preserve the parent protocol's minimum DOA counts, clustered tests, winner preservation and unchanged comparison definitions. Collection results alone authorize no policy change.

## Capture and explicit limitations

A separate Fly Machine (Paris, shared 1 CPU, 256 MB) reads Binance USD-M public depth diff, aggTrade, closed 1m kline and observed liquidation streams. REST depth1000 initializes/resynchronizes the local book; maximum 100 request weight in any rolling minute. A 429/418 stops the process. Connections and stored batches never access private exchange endpoints.

DB watch projection every 15s: held symbols, BTC, admitted candidates in their first 65 minutes, NEW signals, latest scanner top10 and recently seen V17 symbols; priority in that order, lexical tie breaking, maximum32. All admitted signal metadata is retained even when not watched. A newly entering top10 symbol may lack prehistory. Record actual missingness; never invent prior observations. Discovery may lag15s, plus API time. Actual fill timestamps come from the existing positions table and are separately windowed. Delayed DB fill registration beyond the 240s ring is a measurable gap.

Keep a 240s memory ring; persist 5s observations only within candidate/fill minus60s to plus120s. Warmup and disconnect intervals are incomplete. Best quotes, spread, depth25/50bp, displayed ask additions/removals, 450USDT buy/sell VWAP, 5s buy/sell flow and maximum1s sell flow are measured. Flow buckets follow local receive time, with interval timestamps/duration; they are not reconstructed exchange-time buckets. Gross displayed additions are not proof of replenishment or spoofing. Snapshot boundary coverage is conservative; incomplete bands remain flagged. The first trade bucket after connect is incomplete. Liquidation stream is explicitly incomplete. Closed BTC minute return includes its source minute; no sector map is supplied, so sector returns remain null.

Closed 1m candles are persisted for held symbols and all admitted candidates through65 minutes, including rejections. Public REST backfill has its own available_at and never becomes a historical model input. Minute candles cannot resolve intraminute stop/trailing ordering or exact maker queue position. Do not report them as exact execution simulation. Maker/taker account fee schedule and actual funding cashflows are unavailable to this public collector and remain null. Actual entry/exit fees are joined later from existing exchange_trade_fills.v17_position_id; no estimated exit fees replace actual records. No authenticated exchange credential is added.

The worker receives only a dedicated ingestion token. The Edge endpoint authenticates it, accepts watch/ingest/status only, and uses the platform service role internally. This is a code-enforced API boundary, not a claim that the Edge service role itself is least-privilege. The public RPC is security invoker, executable only by service_role. Data tables are in an unexposed private schema with RLS and no anon/authenticated grants. No trading table INSERT/UPDATE is present in the collector path.

## Bounds, stop and cost

One process lease90s prevents concurrent writers; DB transaction locking serializes global budgets. Maximum500MB cumulative accepted serialized requests, 200,000 authenticated API operations,400 rows/request,500KB request,8KB row,32 symbols/request. Physical private tables stop at1.2GB. Idempotent UUID batches never double-charge bytes. Candidate cap2000 stops admission; admitted candidates finish until the fixed end. This differs from immediate termination in the draft, preserving final candidate outcome coverage without enlarging admission.

Worker stops at fixed end, stale control90s, disabled control, rate-limit response, queue1200 rows, or RSS230MB. Its container is limited256MB; no restart, auto-destroy on exit, no public ports, volumes or dedicated IPv4. A crash ends capture and remains a gap; no autonomous restart. A DB stop takes effect on the next call (normally15s); already accepted data remains. Retry queue is bounded and cannot affect order execution.

Provisioning envelope: one shared1x256MB machine for<=336h, <=500MB accepted upload, <=1.2GB additional DB physical data, <=200k successful authenticated Edge operations, zero LLM tokens. Fly published example shared256MB compute $0.0028/hour gives about$0.94/14d; region/provider rates and included Supabase quotas must be checked. $25 is the operator-approved incremental budget, not an invoice guarantee or provider billing hard cap. Resource limits and auto-destroy bound normal usage; account-wide spending is outside this collector. No paid upgrade or extra quota is provisioned. Retention cleanup is restricted to this schema: observations older14d, batch IDs older2d, metadata/control retained90d; no trading records are deleted. A dedicated daily cleanup job, if installed, is included in the deployment receipt.

## Operational acceptance and rollback

Require authentication rejection, SQL permission/budget/lease/idempotency tests, stream sequence tests, typecheck, Docker boot/config checks, real heartbeat and fresh public candles/books, plus unchanged executor SHA. Observe candidate windows naturally; do not place a canary trade. If no fill occurs, state that fill-linked collection has not yet been demonstrated.

Rollback: UPDATE doa_capture.control SET enabled=false WHERE id=1; worker exits and Fly destroys the machine. Revoke the dedicated edge_internal_tokens row if necessary. Unschedule only doa-capture-retention. Keep evidence; no executor deployment, trade cancellation or protective order change. Deployment workflow refuses to replace an existing machine without a separate reviewed operation.

현재 배포판은 `6.8.1-RESIDUAL-LABEL-INTEGRITY`이다. v6.8의 검증형 Pareto
정책 승격 구조를 유지하면서, 청산 후 남은 quantity-step 잔량을 가짜 손실로
기록하던 회계·학습 라벨을 수정한다.

- 업데이트: [`UPDATE_v6.8.1.md`](./UPDATE_v6.8.1.md)
- 변경 내용: [`CHANGELOG-v6.8.1.md`](./CHANGELOG-v6.8.1.md)
- 검증 기록: [`VALIDATION_v6.8.1.md`](./VALIDATION_v6.8.1.md)

- v6.8 외부 검토 요청서: [`MODEL_REVIEW_v6.8.0.md`](./MODEL_REVIEW_v6.8.0.md)

아래 문서의 초기 구축 설명 중 버전별 기본값은 누적 마이그레이션의 최신 값을
우선한다.

업비트 **KRW 현물**과 바이낸스 **USDT 현물**을 5분마다 통합 스캔하고, 열린 포지션을 15초마다 감시·청산하는 자기교정형 자동매매 엔진입니다. 브라우저를 열어둘 필요가 없습니다.

## 핵심 구조

```text
Fly.io 고정 egress IPv4 Gateway
  ├─ 5분마다 Upbit + Binance 통합 스캔 호출
  ├─ 15초마다 양 거래소 포지션 감시
  ├─ 거래소별 인증·주문·조회·취소·재조정
  └─ 주문상한·일일매수상한·마켓·중복주문 방어
                         ↓
Supabase
  ├─ market-scanner      추세·구조·호가·체결·비용·이벤트 판정
  ├─ market-autotrader   자금배분·진입·손절·익절·시간청산·회로차단
  ├─ market-learning     실거래/PAPER 성과 학습·승격·롤백
  └─ Postgres            추천·주문·체결·포지션·손익·학습 증거 영구 저장
                         ↓
Upbit KRW Spot / Binance USDT Spot
```

Supabase Edge Functions는 고정 발신 IP가 아니므로, 거래소 인증 주문은 고정 egress IPv4를 가진 별도 게이트웨이만 실행합니다. API 키는 Fly Secret에만 저장합니다.

## 실행 주기

- 전 종목 통합 스캔: 5분
- 포지션 감시·손절·익절: 15초
- 실전 포워드 학습: 매시간
- 450일 워크포워드 교정: 매주

## 최초 상태

API 키를 등록해도 최초 모드는 `PAPER`입니다. 제한 실거래는 GitHub Actions의 `Auto Trading Control`에서 다음 확인을 거쳐야 시작됩니다.

```text
command: start_live_limited
confirmation: ENABLE_LIVE
```

## 기본 안전선

- 현물만 허용
- 업비트는 `KRW-*`, 바이낸스는 `*USDT`만 허용
- 시장가 매수 금지, 지정가 IOC 진입만 허용
- 청산 목적의 시장가 매도만 허용
- 출금·입금·이체·마진·선물·레버리지 기능 미구현
- 총 동시 보유 4개, 거래소별 최대 2개
- 동일 기초자산의 양 거래소 중복 노출 차단
- 종목당 총자산 최대 5%, 거래당 위험예산 0.5%
- 업비트 1회 100,000원/일 300,000원, 바이낸스 1회 100 USDT/일 300 USDT 기본 상한
- 일일 손실 1.5%, 주간 손실 3%, 연속 손실 3회에서 신규 진입 차단
- 기존 수동 보유 종목에는 자동 진입하지 않음
- 실제 잔고가 봇 장부보다 작으면 신규 진입 자동 정지
- 주문 결과가 불명확하면 동일 client identifier로 조회하며 중복 주문하지 않음


## v5.2 운영 대시보드

GitHub Pages에 스캐너와 자동매매 운영 대시보드가 함께 배포됩니다. 대시보드는 거래소 API 키와 대시보드 제어 토큰을 코드에 저장하지 않으며, 브라우저에서 `DASHBOARD_ACCESS_TOKEN`을 입력한 현재 페이지 메모리만 계좌와 제어 API에 접근합니다.

- 업비트는 **KRW 기준**, 바이낸스는 **USDT 기준**으로 운용 한도를 각각 설정
- 거래소별 `전액` 또는 `선택 금액` 운용
- 보호 원화·보호 USDT를 별도 설정
- 신규 매수 중지, 출금 모드, 계좌 대조, PAPER/LIVE_LIMITED 전환, 비상 청산
- 거래소별 신규 매수를 꺼도 기존 포지션의 손절·익절·시간청산 감시는 유지
- `즉시 재개 + 지금 스캔` 버튼은 6시간 등의 대기시간 없이 장부 대조 후 즉시 신규 진입을 열고 통합 스캔을 시작
- 수동 매도·입금·출금 등 봇 주문 외 KRW/USDT 변동 감지 시 신규 진입 자동 중지 및 실제 잔고 기준 장부 조정
- 수동 개입 거래는 자기교정 학습 표본에서 제외
- 수동 지정가 매도로 봇 보유 자산이 잠겨 있거나 비상 청산이 끝나지 않은 경우 재개 거부
- PAPER와 LIVE_LIMITED의 손실·진입 회로 통계는 서로 섞이지 않음

`전액`은 잔고를 한 주문에 모두 넣는 의미가 아닙니다. 업비트는 KRW, 바이낸스는 USDT 현금과 봇이 보유한 포지션만 자본 기준으로 삼고 보호금을 제외합니다. 사용자가 별도로 보유한 코인의 평가액은 운용 한도를 부풀리지 않습니다. 실제 주문 크기는 손절거리·거래당 위험·종목당 비중·1회 주문 상한을 다시 적용합니다.

## v6.8.1 청산 잔량 무결성

거래소 주문 step 때문에 최종 청산에서 매도하지 못한 소량 코인은 계좌 자산으로
남는다. v6.8.1은 이를 `residual_quantity`와 `residual_value_quote`로 보존하고,
실현손익과 온라인 학습 라벨에 경제적 가치를 포함한다. 재구성할 수 없는 과거
라벨은 `LEGACY_UNVERIFIED`로 분리해 학습에서 제외한다.

## 자기교정

실제 종료 거래는 같은 후보의 가상 결과보다 우선합니다. 실거래는 PAPER보다 더 높은 가중치로 학습됩니다.

학습 항목:

```text
실제 평균 체결가와 슬리피지
실제 수수료 추정 및 순손익
MFE / MAE
손절·목표·추적·시간청산 원인
고점 포착률
거래소·마켓별 성과 편향
```

포워드 학습은 주간 워크포워드 안전선보다 진입 기준을 느슨하게 만들 수 없습니다. 충분한 BUY 표본, 양의 기대수익, Profit Factor, 낙폭, 종목 집중도, 롤링 검증을 모두 통과한 challenger만 승격되고 최근 성과가 악화되면 이전 프로필로 롤백됩니다.

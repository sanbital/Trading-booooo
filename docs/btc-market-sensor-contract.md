# BTC market sensor contract

BTCUSDT remains a priority-1 MARKET_SENSOR. Watch entries carry an array of roles; OPEN_POSITION remains priority 0, scanner leaders and candidates retain their priorities. Multiple roles coexist. The caller must explicitly request its intended contract.

`doa_market_sensor_context_v1(symbol, as_of)` supplies MARKET_SENSOR_CONTEXT_V1. It requires 24 contiguous 5-second buckets plus a causal predecessor for the initial mid, complete books and trade sequences, causal fresh book/flow receive and exchange timestamps, DB ingestion before cutoff, and a received closed BTC 1-minute candle for each point. Missing or null evidence fails closed. Stale/future buckets and unavailable candles are never synthesized. The prior transport and sequence checks are preserved.

Each point exposes mid and 5-second mid change, best bid/ask, spread, taker buy/sell quote, trade count/arrival rate, closed `btc_return_1m`, candle provenance, and observed depth/imbalance. The client derives 5/15/30/60/120-second returns from actual sampled mids, not interpolated prices. Each candle return is close/open minus one of the last causally received closed candle; it is not an open candle or a trailing mid return.

Observed depth includes only the intersection of the requested 25bp band and the original synchronized snapshot boundaries. It excludes isolated diff levels beyond those boundaries. `depth_coverage_complete`, per-side `depth_*_coverage_bps` and boundaries identify actual coverage. A partial depth is never named full 25bp depth or extrapolated. No snapshot levels or stale prices are created. Intrinsically shallow snapshots still do not trigger repeated resyncs.

`doa_context_for_role_v1` dispatches MARKET_SENSOR separately. TRADE_CANDIDATE, SCANNER_LEADER and OPEN_POSITION always call the unchanged `doa_gpt_capture_context_v3`, including for BTC. Missing BTC trade coverage returns `TRADE_CONTEXT_UNAVAILABLE_DEPTH_COVERAGE`. OPEN_POSITION requires a matching open position ID. Sensor availability never authorizes a trade or substitutes for trade coverage. The original V3 function definition and its `coverage_25=true` predicate are unchanged.

All live model source reads collect the BTC sensor with the same as-of cutoff as the traded symbol. The market packet explicitly separates `capture_context` (TRADE_CONTEXT_V3) from `market_sensor.market_sensor_trajectory` (MARKET_SENSOR_CONTEXT_V1). The frozen review validates the sensor against the exact snapshot cutoff and binds it into the snapshot hash; GPT FIRST and DeepSeek receive identical frozen input. FINAL uses the same snapshot or an independently validated refresh. Post-cutoff events are rejected. Model prompts explain partial depth and sensor limitations; sensor context creates no execution permission.

Tests T01–T14 run actual PGlite RPCs, collector calculations, both provider payloads and cutoff rejection. The production release updates only the existing public collector image, preserving its machine configuration, then samples the sensor and dynamic watch/OPEN contexts for at least 600 continuous seconds. It records source commit, image digest, latencies, candle updates and depth metadata. No verification orders or trading configuration writes are permitted.

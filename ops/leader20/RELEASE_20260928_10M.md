# 10분 Top 10 production 배포 및 정합성 확인

**상태: 코드·DB 배포 완료, 새 10분 유료 리뷰 및 제공자별 한도 활성화 보류.** 후보 포착 품질과 응답 신뢰성 검증이 실패했다. `leader20_batch_control.enabled=false`, 두 `ai_provider_limits.enabled=false`를 유지했으며 release receipt를 통과로 꾸미지 않았다. 기존 전략의 30분 제한과 mixed AI 월 $95 정책이 계속 적용된다. 따라서 현재 10분 묶음이 상시 운영 중이라고 표시하면 안 된다.

## 운영 기준과 변경

- 최신 main `e104c14896d1fc5a5e2d1e8498e1e7f39e4e2066` 및 PR #228의 이전 head `b98a547a8bc914d64920216e0c3f9eca546482b0`를 계승했다. 배포 직전 main을 다시 fetch했다. QNT collector, capture ingest, gateway 및 다른 작업의 release request는 수정하지 않았다.
- [최초 운영 감사](BATCH_AUDIT_20260928.md)의 Top 20/6시간 순위 갱신, Top 10 관찰, 24개 연속 5초 버킷, 일 $3/신규 진입 $2.50/보호 $0.50 설정을 계승한다. 10분은 신규 묶음 리뷰의 설정 주기이며 순위 재선정 주기가 아니다.
- 한 요청에 10개 ID와 각 정상 종목의 원본 24개 경로를 담는다. 원본 열·시간·정밀도를 보존했다. DS PASS만 독립 GPT FINAL로 보내며 주문 직전 RECHECK는 더 최신 경로를 요구한다. SKIP은 해당 snapshot에만 적용한다.
- 종목 ID·시각·버전 외에 근거 셀을 검증한다. 서버가 해당 종목의 원본 수치를 붙이고 알 수 없는 필드, 중복 셀, 잘못된 수치·형식을 개별 차단한다. **셀 위치가 맞는 것만으로 경제적 해석이 맞다고 보장하지 않는다.**
- 모델이 긴 SHA를 잘못 복사한 사례를 반영해 응답에는 16자 reference를 사용하고 서버에는 전체 SHA-256을 보존한다. 종목·버전·마지막 시각은 모두 일치해야 한다.
- 미체결 주문 생성 시 capacity가 0이 되어 자신의 REVIEWING event까지 퇴역시키는 문제를 수정했다. 해당 pending intent의 소유 event만 유지하고 다른 오래된 후보는 폐기한다.
- 강한 증거 변화로 추가 호출할 때 남은 정기 10분 호출의 추정 비용을 먼저 확보한다. 부족하면 `EXTRA_BATCH_BUDGET_RESERVED`와 추가 필요액을 기록한다. 모델 통과율 조정은 하지 않았다.
- 새 원장은 제공자·모델·목적·실제 토큰·캐시·비용·불명 예약을 추적한다. legacy 비용은 복사하지 않고 읽기 시 배분한다. public 월 합계가 새 원장을 한 번만 포함하도록 수정했다. 저장 $5, native protection과 기존 보호 예산 규칙은 유지한다.

## 재생·경합·보호 검증

[원본 판단, job key, 비용, 경합 및 배포 증거](evidence/20260928-release-verification.json).

- Node **1,448/1,448**, Deno **1,055/1,055 + 13 steps**, 세 Edge type check 통과. 마지막 근거 검증 수정 후 관련 30건도 통과했다. 유효 24버킷 보존, gap/stale/역전, 일부 ID 누락·중복, JSON·API 실패, 예산 거부, 정산·취소·UNKNOWN, 10분/30분 분리, 슬롯 전환, 오래된 응답 및 주문 전 재확인을 포함한다.
- 실제 PostgreSQL의 격리 schema에서 4개 session이 같은 call key를 동시에 예약: 1개만 생성. 두 session이 월 잔액 $0.03에서 각각 $0.02 예약: 1개만 생성, 나머지는 추가 $0.01 필요로 차단. 세 session의 동시 batch claim: 1개만 생성. 실제 주문이나 production ledger를 쓰지 않았다.
- 격리된 pending OPEN_LONG 생성으로 슬롯 1→0, 자기 주문 event 유지·다른 event 퇴역, 미전송 주문 거절로 0→1 및 즉시 wake 1개를 확인했다. synthetic schema는 종료 후 삭제했다. 실제 거래소 주문 경합이나 production 슬롯 전환을 수행한 것으로 표현하지 않는다.
- 운영 Top 10 요청 3회와 frozen Top 10 비교 1회, 역사 반례 묶음 1회를 추가 측정했다. 각 요청은 10개 ID를 한 API 요청으로 보냈다. QNT가 두 실측에서 noncausal로 개별 차단됐고 정상 종목 결과는 독립 처리했다. 이후 production 조회에서는 QNT 포함 10종목 모두 24버킷 AVAILABLE이었다.
- **반례 검증 실패:** 기존 DS SKIP/GPT BUY이며 24버킷이 보존된 10건을 재생했다. 새 DS는 PASS 3, SKIP 3, WAIT 2, 잘못된 근거 필드로 BLOCKED 2였다. **7/10이 GPT로 전달되지 않는다.** 선택된 어려운 반례이며 서로 다른 시점의 snapshot이므로 전체 recall·수익 기회 손실률은 아니다. 10건을 맞추려고 BUY/PASS를 강제하지 않았다.
- **응답 신뢰성 실패:** 가장 최근 실제 Top 10 측정에서 QNT 1개는 데이터 문제, 정상 데이터 9개는 필드명 대신 숫자 인덱스를 반환하여 모두 `EVIDENCE_REQUIRED`로 차단됐다. raw PASS 4개도 승인되지 않았다. JSON/HTTP 성공과 유효한 판단 완료를 구분한다.
- frozen 동일 경로 GPT 비교는 4회 성공, 모두 SKIP이었다. 두 비교는 legacy claim의 500ms lock timeout으로 호출 전 취소됐고, 이후 진단 비교를 순차 예약하도록 고쳤다. BUY 양성 표본이 없어 이 4건으로 새 경로 recall을 증명할 수 없다. 최신 DS가 전부 차단되어 fresh production FINAL 분기는 이번 실측에서 호출되지 않았다.
- malformed JSON·timeout·재시도·예산 고갈·HOLD/EXIT의 보호 지속성은 회귀 검증했다. 실측 시 보유 포지션이 없어 실제 HOLD/EXIT 체결을 검증하지 않았다. 수동 주문은 0건이다.

## 남은 활성화 기준

근거 형식과 의미가 안정적으로 맞는 동일 시점 Top 10 재생, 기존 GPT BUY 반례의 후보 보존, fresh 단일 FINAL/RECHECK의 실측, 시간대별 비용 꼬리와 보유 리뷰 여유를 검증해야 한다. 이 기준을 통과하기 전에는 release receipt의 recall/budget gate를 통과로 기록하거나 10분 운용 스위치를 켜지 않는다. 코드·장부 정합성 통과를 거래 판단 품질 통과로 대체하지 않는다.
